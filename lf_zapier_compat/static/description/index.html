Stop legacy XML-RPC clients from breaking your search() calls

Zapier's "Odoo ERP Self Hosted" app, and a handful of other older XML-RPC clients, still call search() using the pre-v8 calling convention, where context was passed positionally instead of as a keyword. Modern Odoo rejects that shape outright. This module recognizes it and repairs the call, with no effect on anything that calls search() normally.

What breaks today, without this module

TypeError: BaseModel.search() takes from 2 to 5 positional arguments but 6 were given

Why you need this

One narrow fix, installed once, and Zapier polling stops failing.

No more failed Zapier polling

Triggers that poll a model with search() stop throwing TypeError the moment this module is installed. Nothing changes on the Zapier side.

Fully backward compatible

Only the exact legacy shape — a stray positional integer where the domain belongs — gets intercepted. Every other caller passes straight through untouched.

Zero configuration

Install it and it works. There is nothing to set up: no settings page, no menu, no view.

Frequently asked

Does this change behavior for normal users?

No. It only intercepts one specific, otherwise-invalid legacy call shape. Every other call to search() runs through Odoo's original implementation exactly as before.

Which RPC clients does this fix?

Confirmed against Zapier's "Odoo ERP Self Hosted" app, and applicable to any other XML-RPC client still built on the pre-v8 search(domain, offset, limit, order, context) convention.

Does it work on Community and Enterprise?

Yes. It depends only on base, so it behaves the same way on Community and Enterprise, on-premise or Odoo.sh.
