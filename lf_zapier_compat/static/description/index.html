Zapier RPC Compatibility

Stop legacy XML-RPC clients like Zapier from breaking your search() calls

Zapier's "Odoo ERP Self Hosted" app - and a few other legacy XML-RPC clients - still call search() using the pre-v8 convention, where context was passed as a positional argument: search(domain, offset, limit, order, context[, count]).

Modern Odoo no longer accepts context positionally at all, so that dict lands in search()'s count slot and the call fails with TypeError: BaseModel.search() takes from 2 to 5 positional arguments but 6 were given. This module detects that legacy call shape and reinterprets it correctly - with zero effect on any normal, modern call.

FAQs

Does this module change any behavior for normal users?

No. It only intercepts one specific, otherwise-invalid legacy call shape. Every other call to search() is passed straight through to Odoo's original implementation.

Which RPC clients does this fix?

It was confirmed against Zapier's "Odoo ERP Self Hosted" app, and applies to any other XML-RPC client still using the pre-v8 search(domain, offset, limit, order, context) calling convention.

Does this work on both Community and Enterprise?

Yes. It only depends on base and works the same way on Odoo Community and Enterprise, on-premise or Odoo.sh.
